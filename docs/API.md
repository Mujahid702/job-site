## 1. Resume OS API Endpoints

### 1. ATS Evaluator & Enhance (`/api/resume/evaluate`)
Evaluates resume text and calculates scoring details.
- **Method**: `POST`
- **Owner**: Developer A (Resume OS Lead)
- **Dependencies**: Gemini LLM API, Upstash Redis cache lookup
- **Auth Level**: Authenticated User (`x-gemini-api-key` optional user override)
- **Authorization**: Active user session required (checked via Supabase auth header)
- **Rate Limits**: 60 requests / minute (monitored via Upstash Redis sliding window)
- **Caching**: 24-hour TTL in Upstash Redis cache (caching key: `ats:[sha256_hash_of_input]`)
- **Database Tables**: `public.resume_scans`, `public.resume_analytics`
- **Expected Latency**: 120ms (Cache hit) / 4500ms (Cache miss / Gemini execution)
- **AI Model Provider**: Google Gemini (`gemini-3.5-pro` for deep parsing)
- **Logging & Telemetry**: Background cost logging via `lib/ai/costTracker.ts` to `public.analytics_events` table
- **Failure Recovery**: Fallback chain triggers Groq model failover if Gemini returns error code 429 / 503
- **Input Parameters**:
  ```json
  {
    "resumeText": "String containing raw resume text",
    "targetRole": "Software Engineer"
  }
  ```
- **Response Shape (200 OK)**:
  ```json
  {
    "success": true,
    "data": {
      "atsScore": 78,
      "roleFitScore": 82,
      "feedback": {
        "missedKeywords": ["Kubernetes", "gRPC"],
        "formatIssues": ["Too many columns", "No contact phone"],
        "readabilityScore": 90
      }
    }
  }
  ```

### 2. Job Match Scanner (`/api/resume/jd-match`)
Compares candidate resume text against target job description.
- **Method**: `POST`
- **Owner**: Developer A (Resume OS Lead)
- **Dependencies**: Gemini LLM API, Upstash Redis cache
- **Auth Level**: Authenticated User
- **Authorization**: User session context validation
- **Rate Limits**: 30 requests / minute
- **Caching**: 24-hour TTL in Upstash Redis (caching key: `jd:[sha256_hash_of_input]`)
- **Database Tables**: `public.jd_matches`
- **Expected Latency**: 100ms (Cache hit) / 3800ms (Cache miss)
- **AI Model Provider**: Google Gemini (`gemini-3.5-flash`)
- **Logging & Telemetry**: Latency tracking logs registered inside `public.analytics_events`
- **Failure Recovery**: Falls back to Groq LLaMA models if connection blocks
- **Input Parameters**:
  ```json
  {
    "resumeText": "Raw resume text...",
    "jdText": "Job description text requirements...",
    "jobRole": "Full Stack Developer"
  }
  ```
- **Response Shape (200 OK)**:
  ```json
  {
    "success": true,
    "matchScore": 85,
    "analysis": {
      "gapAnalysis": "Candidate lacks relational database optimization focus.",
      "keywordMatches": ["React", "TypeScript", "Node.js"],
      "missingSkills": ["PostgreSQL indexing", "Connection pool management"]
    }
  }
  ```

## 4. Recruiter CRM & Trust Hub API Endpoints

### 1. Recruiter Validation OTP (`/api/recruiter-verifications/otp/send`)
Triggers OTP verification code to recruiter's LinkedIn email.
- **Method**: `POST`
- **Owner**: Developer B (Partnerships Lead)
- **Dependencies**: LinkedIn API validator integration
- **Auth Level**: Recruiter Access (Verified via LinkedIn SSO)
- **Authorization**: Verified recruiter role check (admin approves)
- **Rate Limits**: 5 requests / hour (highly restricted to prevent spamming)
- **Caching**: Disabled (one-time codes)
- **Database Tables**: `public.recruiter_verifications`
- **Expected Latency**: 800ms
- **AI Model Provider**: None (Stateless cryptographical OTP)
- **Logging & Telemetry**: Audit logs saved in `public.audit_logs`
- **Failure Recovery**: Returns formatted error warning to retry after 1 hour
- **Input Parameters**:
  ```json
  {
    "recruiterEmail": "recruiter@amazon.com",
    "linkedInUrl": "https://linkedin.com/in/recruiter-handle"
  }
  ```
- **Response Shape (200 OK)**:
  ```json
  {
    "success": true,
    "message": "OTP verification code dispatched."
  }
  ```

## 5. Security & Error Code Reference

When an API call fails, the response envelope will return the standard error structure:

- **Error Format**:
  ```json
  {
    "success": false,
    "error": "Error message description"
  }
  ```

### HTTP Status Codes:
- `400 Bad Request`: Input validation failed (e.g. missing `resumeText` in ATS scan).
- `401 Unauthorized`: Missing auth token or invalid verification key.
- `403 Forbidden`: Authenticated user lacks permission (e.g., non-admin accessing `/api/admin/*`).
- `429 Too Many Requests`: Upstash Redis rate limiter blocked request.
- `500 Internal Server Error`: Backend adapter failed or AI service timed out.
